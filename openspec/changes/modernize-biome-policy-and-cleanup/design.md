## Context

The evidence records divergent cleanup stacks, a 28,840-diagnostic RI baseline,
unsafe ordering fixes, and generated OpenAPI formatted outside its generator. The
selection census is also mutable: the later connector correction changed 2,550 to
2,546 selected files. Counts are evidence, not authority.

## Goals and non-goals

Goals are deterministic selection, rule policy, generated drift protection, bounded
diffs, and zero untriaged findings. This does not promise raw zero diagnostics by
silencing rules, shrinking selection, blanket suppression, or unexecuted tests. It
does not carry forward `befc56a35`'s 910-file RI output or alter generated OpenAPI
without its generator in the same contract tranche.

## Decisions

- Record base SHA, Biome/Ultracite/Node/pnpm versions, config hashes, both selected
  file sets, exclusions and reasons, diagnostic tuples, histograms, JS/MJS inventory,
  test manifest, and generator input/output hashes.
- Require Biome and Ultracite selection equality. Any selection change requires a
  reviewed artifact-policy decision plus a mutation assertion; a lower diagnostic
  count with fewer selected files fails.
- Classify each finding as real defect, useful style, tool mismatch, or domain
  exception. Accepted rules and narrow package/rule suppressions are policy entries;
  inline suppression is allowed only with a tested invariant. Completion means zero
  untriaged findings and zero new baseline regressions, not raw metric zero.
- Exclude generated OpenAPI and site `.source` from formatter input, while running
  their generator/checker; generated output changes only when its generator and
  contract test are in the same tranche. Executable fixtures remain selected;
  captured provider data is excluded only by exact inventoried paths.
- Land policy/selection, formatter-only cohorts, braces/numeric/interface cohorts,
  and semantic async/loop/regex/null/delete/control-flow/complexity repairs as
  separate bounded units with independent checkers. Formatter-only excludes sorted
  keys and import organization by default because ordering can be observable.
- Shared configs, manifests, lockfiles, runners, generators, Docker inputs, exports,
  and sensitive RI subsystems are integration-owned and serialized.
- `performance/noJsxPropsBind` is adjudicated a tool mismatch for `apps/site` and
  `apps/console`: both apps have zero `React.memo`/memoized-child/props-identity
  consumers (verified by grep across `src/`), so every flagged handler is a plain
  DOM/unmemoized-component prop where `useCallback` would be inert memoization.
  Policy entry: rule off via a single documented `overrides` block scoped to
  `src/**/*.tsx` in each app's `biome.jsonc`, replacing 131 per-line
  `biome-ignore` suppressions. Any handler feeding a real memoized consumer keeps
  (or gains) `useCallback`; none existed at adjudication time. Owner: PDP-Connect
  app maintainers. Expiry: re-adjudicate if either app adopts `React.memo`/list
  virtualization, or if Ultracite's rule becomes consumer-aware.

## Alternatives rejected

The 910-file checkpoint is too broad to review and lacked the right backend proof.
Bulk autofix and raw diagnostic zero optimize a proxy and can change ordering,
failure timing, or generated bytes. A blanket ignore would hide authored source.

## Acceptance checks

Each tranche has a machine-readable receipt and independent checker. Relevant package,
SQLite/PostgreSQL/Docker, generated-contract, test-accounting, and runtime gates run
according to touched paths; final review audits receipts and exceptions rather than
trusting a cumulative count.
